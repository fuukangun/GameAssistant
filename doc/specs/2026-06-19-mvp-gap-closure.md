# MVP Gap Closure Spec

## 背景

当前 App 已跑通离线存档扫描、基础解析、今日计划生成、全局库存、运势展示、重要提醒/推荐行动/角色技能/友谊维系/探索进度等主界面。物品解析、最小静态资料库、商店开放基础判断、种子证据、洒水条件、钓鱼装备证据和路线进度基础展示已完成或基本完成，后续缺口集中在空地精确扫描、完整鱼类窗口、社区中心 bundle 明细等更细的规则。

本 spec 只覆盖剩余 MVP 缺口，不扩展到完整百科级资料库或实时 Mod。

## 目标

1. 消除明显误导性的 `Unknown Item` 和不必要的 `待解析`。
2. 用小而可信的静态资料库提升礼物、库存、种植建议质量。
3. 将复杂功能拆成可独立验证的小任务，避免一次性做大而不可靠的规则系统。
4. 每个任务都必须有测试覆盖，无法可靠判断时保留低置信或明确“不支持”文案。

## 非目标

- 不做全 NPC 礼物数据库。
- 不做全物品、全鱼类、全商店日程数据。
- 不做 SMAPI 实时模式。
- 不写回或修改游戏存档。
- 不为 Mod 物品承诺完整解析。

## 当前缺口任务

### Task A: 物品解析质量

状态：已完成。

范围：
- 过滤空库存槽位，例如 `xsi:nil`。
- 物品名称按 `Name/name/DisplayName/displayName/item catalog/id fallback` 解析。
- 物品 ID 按 `ItemId/itemId/parentSheetIndex/QualifiedItemId` 解析。
- Qualified item id 例如 `(O)66` 要能匹配内置物品目录和礼物偏好。

验收：
- App 中不再出现 `Unknown Item`。
- 只有 ID 的常见物品显示中文名；未知 ID 显示 `物品 #ID`。
- 背包、储物箱、冰箱都遵守同一规则。

### Task B: 最小静态资料库

状态：基本完成。

范围：
- 新增内置物品目录，只收 MVP 已用和少量礼物数据。
- NPC 偏好先覆盖 Sebastian、Abigail、Leah、Linus、Shane 的最爱礼物。
- 不录入 disliked/hated，不做通用最爱规则。

验收：
- 已录入 NPC 的最爱礼物可以从全局库存匹配。
- 所有 `lovedItemIds` 都能在物品目录找到中文名。
- 未录入 NPC 显示“该NPC偏好待录入”。

### Task C: 商店开放基础判断

状态：已完成。

范围：
- 探索进度中不再固定显示“商店是否开放：待解析”。
- 只做基础规则：皮埃尔周三休息、Joja 通常开放、节日当天提示营业可能受影响。
- 不做 NPC 行程、剧情事件、特殊闭店细节。

验收：
- 春季第3天显示皮埃尔周三休息。
- 非周三显示通常开放。
- 节日当天显示营业可能受影响。

### Task D: 种子与空地

状态：最小闭环完成。

范围：
- 从全局库存识别常见种子。
- 种植建议证据中展示“库存是否已有种子”。
- 空地先不做精确地块扫描，只显示“空地未解析”。

验收：
- 如果库存有推荐作物对应种子，种植建议证据显示种子来源。已完成。
- 如果没有种子，建议仍可基于金币购买，但保持中/低置信。已完成。
- 探索进度展示已识别种子，并明确空地未精确解析。已完成。

### Task E: 洒水条件

状态：最小闭环完成。

范围：
- 先解析是否存在洒水器物品或农场对象中的洒水器。
- 不计算覆盖范围。

验收：
- 探索进度显示“检测到洒水器/未检测到洒水器/待解析”。已完成。
- 农业建议不因为检测到洒水器就声称无需浇水。已完成。

### Task F: 水域与鱼类窗口

状态：最小闭环增强完成。

范围：
- 暂不做全鱼类窗口。
- 先将钓鱼建议的“不确定项”拆清：水域未解析、时间窗口未解析、鱼竿/鱼饵已解析或未解析。

验收：
- 钓鱼建议能利用已解析鱼竿/鱼饵证据。已完成。
- 探索进度展示鱼竿/鱼饵状态。已完成。
- 在季节和天气匹配时展示少量已支持鱼种，例如春/秋雨天鲶鱼；其他水域与时间窗口仍明确标注未解析。已完成。
- 不输出具体鱼种推荐，除非后续补静态鱼类表。已完成。

### Task G: 社区中心/Joja 进度

状态：基础展示完成，明细待做。

范围：
- 保持路线基础判断。
- 探索进度展示社区中心总体完成度或 Joja 项目基础计数。
- 后续逐步解析 bundle 明细和 Joja 项目价格/资金缺口。

验收：
- 路线未知时不生成强相关建议。
- Joja 路线不展示社区中心收集建议。
- Joja 路线可显示已购买项目数量。已完成。

## 执行顺序

1. Task A: 物品解析质量。已完成。
2. Task B: 最小静态资料库。基本完成，未录入 NPC 使用“该NPC偏好待录入”兜底。
3. Task C: 商店开放基础判断。已完成。
4. Task D/F 并行：种子库存证据、钓鱼建议证据增强。最小闭环完成。
5. Task E: 洒水条件。最小闭环完成。
6. Task G: 社区中心/Joja 进度。基础展示完成，明细待做。

## 测试策略

- 每个 task 至少一个 focused unit test。
- 解析类任务在 `parseSave.test.ts` 覆盖 XML 结构。
- 展示/格式化类任务在 app 层测试覆盖。
- 计划建议类任务在 `generatePlan.test.ts` 覆盖 evidence/uncertainty。
- 完成批次后运行 `npm run typecheck`、`npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml`。
