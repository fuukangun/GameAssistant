# 待实现和优化任务 - 20260619 v1

## 背景

当前 App 已具备离线存档扫描、基础存档解析、今日天气手动选择、今日计划生成、全局库存、重要提醒、推荐行动、角色技能、友谊维系、探索进度、运势展示和 Tauri 打包能力。剩余工作不再是“能不能跑起来”，而是让建议更可信、更完整、更像一个可以长期迭代的独立产品。

本清单按明显产品缺口、规则数据缺口、工程完善缺口三类梳理。

## 一、明显产品缺口

### P1. Joja 资金建议

现状：
- App 能判断 Joja 路线，并能展示基础项目计数。
- 还没有展示未购买项目、项目价格、最低价未完成项目、当前金币差额。

目标：
- Joja 路线下展示“下一个可购买项目”和“还差多少金币”。
- 赚钱优先模式下，将 Joja 资金缺口转成推荐行动或重要提醒。
- 社区中心路线下不显示 Joja 资金建议。

### P1. 社区中心 Bundle 明细

现状：
- App 只展示社区中心总体进度或基础完成状态。
- 没有解析具体房间、收集包、缺失物品、库存可交付项。

目标：
- 展示已识别的收集包进度。
- 根据全局库存提示“当前可交付物品”。
- 对无法可靠解析的 bundle 明确降级，不输出强建议。

### P1. 完整鱼类规则

现状：
- 只支持少量鱼类窗口提示，例如春/秋雨天鲶鱼。
- 钓鱼收益仍是粗略区间。

目标：
- 建立最小鱼类静态数据表：鱼名、季节、天气、时间、地点、基础售价。
- 探索进度展示今日可钓鱼类。
- 推荐行动中的钓鱼收益至少能引用已支持鱼种。

### P2. 空地与农场地块扫描

现状：
- App 能识别种子和洒水器，但不能判断可种植空地。

目标：
- 解析农场可耕种地块、已耕地、已种植地块。
- 探索进度展示“可用空地：已解析/未解析”。
- 种植建议避免在明显没有空地时继续强推。

### P2. NPC 礼物偏好覆盖

现状：
- 只覆盖少量 MVP NPC 的最爱礼物。
- 未录入 NPC 显示“该NPC偏好待录入”。

目标：
- 扩展更多 NPC 的最爱礼物，至少覆盖常见村民。
- 礼物建议显示最爱/喜欢/一般三个等级中的已匹配项。
- 静态数据必须有完整性测试，避免偏好 ID 没有物品名。

## 二、规则数据缺口

### R1. 作物 ROI 规则

现状：
- 基础作物表很小，主要用于证明“本季能否成熟”。

目标：
- 扩展基础作物表，覆盖春夏秋常见商店作物。
- 支持复收作物的保守收益估算。
- 区分“已有种子”和“需要购买种子”的置信度。

### R2. 矿洞准备规则

现状：
- 已展示矿洞层数、生命、武器、食物。
- 未解析炸弹、楼梯、矿洞目标层收益和风险。

目标：
- 识别炸弹、楼梯、关键食物。
- 根据当前层数给出 5 层或 10 层目标。
- 运势只保留顶部展示，矿洞建议不显示具体运气数值。

### R3. Joja / Bundle 静态数据

现状：
- Joja 项目 marker 和 bundle 数据都非常粗。

目标：
- 增加 `joja` 静态数据：项目名、价格、marker。
- 增加 MVP bundle 静态数据：房间、收集包、物品 ID。
- 数据版本要能被测试验证。

### R4. 物品目录扩展

现状：
- 物品目录只覆盖 MVP 已用物品和少量礼物。

目标：
- 覆盖作物、鱼、Joja、bundle、常见食物、矿洞物资涉及的物品。
- 未知物品仍保留 `物品 #ID` 兜底。

## 三、工程完善缺口

### E1. 多人存档检测

现状：
- 文档要求多人存档提示“暂未完整支持”。
- 解析器尚未系统检测 `<farmhands>` 等多人字段。

目标：
- 检测多人存档字段并生成 `unsupported_multiplayer` warning。
- UI 展示温和提示，不阻断基础解析。
- 依赖完整单人状态的建议降级。

### E2. 真实存档夹具

现状：
- 单元测试覆盖较多，但真实存档结构样本不足。

目标：
- 增加脱敏真实存档片段夹具。
- 覆盖社区中心中期、Joja 路线、姜岛已开、后期装备、多人字段。

### E3. 静态数据加载边界

现状：
- 多数数据仍以内置 TypeScript 表存在。

目标：
- 为未来 JSON 数据文件预留加载与校验路径。
- 数据损坏时显示“参考数据不可用”，App 不崩溃。

### E4. 打包与回归检查

现状：
- 已能构建 Tauri app。

目标：
- 每轮较大改动后运行：
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - `cargo test --manifest-path src-tauri/Cargo.toml`
  - `npm run tauri:build`

## 推荐执行顺序

1. Joja 资金建议：收益最大，范围较小，适合先做。
2. 完整鱼类规则 MVP：能明显提升钓鱼建议可信度。
3. NPC 礼物偏好扩展：能改善友谊维系 tab 的空白感。
4. 多人存档检测：工程风险控制项，避免误导用户。
5. 社区中心 Bundle 明细：价值高，但解析复杂，应单独 spec。
6. 作物 ROI 和空地扫描：影响农业建议，应分阶段推进。
7. 矿洞准备规则：在更多物品目录完成后推进。
