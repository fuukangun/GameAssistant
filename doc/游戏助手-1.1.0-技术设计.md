> **版本**: v1.0  
> **日期**: 2026-06-27  
> **关联需求**: [游戏助手-1.1.0-需求文档.md](./游戏助手-1.1.0-需求文档.md)

> **目标版本**: 1.1.0  
> **主题**: 推荐可信度增强

---

## 一、设计目标

1. 提升推荐行动可信度，减少已可解析字段导致的“未解析”提示。
2. 保持现有首页、角色技能、友谊维系、探索进度页面结构稳定，只做数据校准、文案修正和必要详情补强。
3. 所有新增解析遵循保守策略：字段语义明确才输出强结论；不明确时输出不确定项并降低置信度。
4. CI 测试只依赖仓库内脱敏 fixture，不依赖本机真实存档路径。
5. 发布流程继续使用现有 Tauri + GitHub Actions，不自动创建 release；所有版本控制操作只在用户明确要求时执行。

## 三、数据模型设计

### 3.1 机器状态

新增机器状态模型，挂载到 `StardewSaveSnapshot`。

```ts
export type MachineStateKind = 'ready' | 'processing' | 'idle' | 'unknown';

export interface MachineStateSummary {
  machineId?: number | string;
  machineName: string;
  location?: string;
  tileKey?: string;
  state: MachineStateKind;
  output?: ProducedItemSummary;
  heldObjectId?: number | string;
  minutesUntilReady?: number;
  parseConfidence: 'high' | 'medium' | 'low';
  unknownFields: string[];
}

export interface StardewSaveSnapshot {
  machineStates?: MachineStateSummary[];
}
```

设计原则：

- `readyMachineOutputs` 保持兼容，继续作为“收取加工产物”的直接输入。
- `machineStates` 是 1.1.0 新增增强字段，主要服务“安排新加工”的置信度。
- 只有能明确识别机器对象、产物状态、剩余时间时，才标记 `ready` / `processing` / `idle`。
- 无法确认的机器必须标记 `unknown`，不得推断为空闲。

### 3.2 农场地块

现有 `FarmPlotSummary` 保留，新增字段只做可选增强。

```ts
export interface FarmPlotSummary {
  plantedCropCount: number;
  tilledTileCount: number;
  occupiedObjectCount: number;
  resourceClumpCount: number;
  buildingCount: number;
  emptyTileCount?: number;
  sprinklerCount?: number;
  sprinklerCoverageParsed?: boolean;
  wateredTileCount?: number;
  parsedFields: string[];
  unknownFields: string[];
}
```

设计原则：

- `emptyTileCount` 只表示“已耕且无作物的地块”，不是全农场可种植面积。
- `sprinklerCount` 只表示检测到洒水器数量。
- `sprinklerCoverageParsed === true` 前，不得声称地块无需浇水。
- 如果无法确认地块和洒水器覆盖关系，种植建议最高 `medium`。

### 3.3 推荐证据和不确定项

现有 `RecommendationItem` 结构继续使用，不新增 UI 层结构。

1.1.0 要求：

- 所有强推荐必须有 `evidence`。
- 不能从存档稳定解析的字段必须进入 `uncertainty`。
- `confidence === 'high'` 时，不允许存在会影响行动成立性的关键未解析字段。

关键未解析字段示例：

| 推荐类型 | 关键字段 |
|---|---|
| 种植 | 季节剩余天数、作物生长天数、金币、种子、空地、洒水覆盖 |
| 加工 | 机器存在、机器状态、原料、辅料 |
| 钓鱼 | 鱼竿、天气、季节、地图解锁、今日可钓鱼类 |
| 下矿 | 普通矿洞层数、生命、武器、食物 |
| 升级 | 当前工具等级、材料、金币、铁匠铺占用状态 |

## 四、存档解析设计

### 4.1 机器状态解析

修改文件：

- `src/shared/types.ts`
- `src/stardew/saves/parseSave.ts`
- `src/stardew/saves/parseSave.test.ts`

解析目标：

- 小桶。
- 罐头瓶。
- 熔炉。
- 鱼熏制机。
- 蛋黄酱机。
- 奶酪压制机。
- 脱水机。
- 树液采集器。

解析策略：

1. 从存档对象树中定位农场、建筑内部、姜岛农场等位置的对象集合。
2. 识别对象是否为目标机器。
3. 读取 heldObject / output / minutesUntilReady 等字段。
4. 字段完整且语义明确：
   - 有可收取产物：`ready`
   - 有输入或剩余时间：`processing`
   - 无输入、无产物、无剩余时间：`idle`
5. 字段缺失或机器结构不符合预期：`unknown`

降级规则：

- `unknown` 不参与高置信加工建议。
- `processing` 不得被用于“安排新加工”。
- `idle` 可以作为高置信加工建议依据，但仍需满足原料和辅料条件。

### 4.2 农场地块解析

修改文件：

- `src/shared/types.ts`
- `src/stardew/saves/parseSave.ts`
- `src/app/farmPlotStatus.ts`
- `src/app/farmPlotStatus.test.ts`
- `src/stardew/planner/generatePlan.ts`

解析范围：

- 已种植作物数量。
- 已耕地数量。
- 已耕空地数量。
- 资源障碍物数量。
- 建筑数量。
- 洒水器数量。
- 已解析字段和未解析字段。

不做范围：

- 不做完整地图坐标建模。
- 不承诺精确农场可种植总面积。
- 不承诺洒水器覆盖每个空地，除非后续明确实现覆盖关系解析。

### 4.3 动物与饲料解析

修改文件：

- `src/shared/types.ts`
- `src/stardew/saves/parseSave.ts`
- `src/stardew/planner/generatePlan.ts`
- `src/app/producedItemActionDetails.ts`

增强目标：

- 动物数量。
- 干草数量。
- 干草可支撑天数。
- 自动采集器产物。
- 今日动物产物是否可收取。

推荐规则：

- 干草不足 2 天：重要提醒。
- 秋季第 25-28 天且干草不足：`must_do`。
- 自动采集器产物进入“收取动物产物”详情。

### 4.4 社区中心与 Joja 校准

## 五、推荐引擎设计

### 5.1 农业推荐

修改文件：

- `src/stardew/planner/generatePlan.ts`
- `src/app/recommendationDisplay.ts`
- `src/stardew/planner/generatePlan.test.ts`

规则：

- 作物无法在季末前成熟：不生成种植行动，只保留季末风险提醒。
- 空地未解析：不输出“可种 N 格”。
- 只检测到洒水器存在但未解析覆盖：置信度最高 `medium`。
- 只有作物、金币、种子、空地、洒水覆盖均明确时，置信度可为 `high`。

### 5.2 加工推荐

修改文件：

- `src/stardew/planner/generatePlan.ts`
- `src/app/producedItemActionDetails.ts`
- `src/app/recommendationDisplay.ts`

规则：

- `readyMachineOutputs` 生成“收取加工产物”。
- `machineStates.idle + 原料 + 辅料` 生成“安排新加工”。
- `machineStates.processing` 不参与安排新加工。
- 没有机器但有高价值原料时，生成“补齐加工设备”。
- 机器状态 unknown 时，加工建议最高 `medium`，并展示不确定项。

### 5.3 钓鱼推荐

修改文件：

- `src/stardew/planner/generatePlan.ts`
- `src/stardew/data/fish.ts`
- `src/app/recommendationDisplay.ts`

规则：

- 没有鱼竿：只推荐“先获取鱼竿”，不推荐钓鱼赚钱。
- 有鱼竿无鱼饵：可推荐钓鱼，但说明效率影响。
- 今日可钓鱼类为空：收益估算 `low`。
- 今日可钓鱼类非空：收益估算至少 `medium`。
- 展示鱼类名称、地点、时间窗口时必须经过国际化格式化。

### 5.4 下矿与骷髅洞穴

修改文件：

- `src/stardew/saves/parseSave.ts`
- `src/app/explorationStatus.ts`
- `src/stardew/planner/generatePlan.ts`

规则：

- 普通矿洞层数最大 120。
- 骷髅洞穴层数使用 `farm.skullCavernLevel`。
- 普通矿洞推进建议目标不得超过 120。
- 下矿建议展示运势等级，不展示 raw `dailyLuck`。
- 缺食物、缺武器、生命过低时，下矿建议降级。
- 骷髅洞穴专项收益/冲层评分作为 P1，不进入 P0。

### 5.5 装备升级

修改文件：

- `src/stardew/data/upgradeRules.json`
- `src/stardew/planner/generatePlan.ts`
- `src/app/recommendationDisplay.ts`

规则：

- 背包升级和工具升级分开建模。
- 工具升级展示当前等级、下一等级、材料、金币、库存是否满足。
- 铁匠铺占用状态未解析时，工具升级最高 `medium`。
- 雨天或浇水压力低时，喷壶升级排序可提高，但不能跳过材料和金币校验。

## 八、性能设计

### 8.1 缓存边界

现有 `snapshotsBySaveId` 继续作为运行时缓存。

规则：

- 切换已缓存存档不得重新读取 XML。
- 刷新当前存档只重新读取当前 `save.path`。
- 文件不存在或移动时，从存档列表和本地导入记录中移除。

### 8.2 避免重复计算

重点检查：

- 友谊礼物匹配。
- 社区中心可交付项。
- 加工产物详情分组。
- 推荐详情弹窗。
- 探索进度。

实现建议：

- React 层使用 `useMemo` 缓存按 snapshot 派生的大列表。
- planner 层保持纯函数，便于测试。
- 不在 render 中重复解析 XML。
