# 游戏助手 1.1.0 - 温室/姜岛农场种植规则技术方案

> **版本**: v1.0  
> **日期**: 2026-06-28  
> **关联需求**: [游戏助手-1.1.0-温室姜岛农场种植规则-补充需求文档.md](./游戏助手-1.1.0-温室姜岛农场种植规则-补充需求文档.md)  
> **关联技术设计**: [游戏助手-1.1.0-技术设计.md](./游戏助手-1.1.0-技术设计.md)  
> **主题**: 温室与姜岛农场种植推荐可信度增强  
> **范围定位**: 1.1.0 P2 可延期能力的实现方案，不改变 1.1.0 P0/P1 发布阻断范围

---

## 一、设计目标

1. 在不破坏现有普通农场种植推荐的前提下，新增温室和姜岛农场专项种植能力。
2. 将“地块解锁”“地块可用”“空地证据”“洒水证据”拆开建模，避免仅凭姜岛开放或温室标记输出过度自信建议。
3. 普通农场、温室、姜岛农场的作物、空地、洒水器和不确定项必须按地点聚合，不能混用证据。
4. 推荐引擎继续保持纯函数，所有新增逻辑可通过 fixture 和单元测试验证。
5. 国际化继续通过统一格式化入口和泄漏测试收口，不在 UI 中直接拼接裸英文地名或作物名。

## 三、数据模型设计

### 3.1 种植区类型

在 `src/shared/types.ts` 中新增：

```ts
export type PlantingZone = 'farm' | 'greenhouse' | 'ginger_island_farm';

export type PlantingZoneUnlockState = 'unlocked' | 'locked' | 'unknown';

export interface PlantingZoneSummary {
  zone: PlantingZone;
  unlockState: PlantingZoneUnlockState;
  usable?: boolean;
  plantedCropCount?: number;
  matureCropCount?: number;
  tilledTileCount?: number;
  emptyTilledTileCount?: number;
  sprinklerCount?: number;
  sprinklerCoverageParsed?: boolean;
  parsedFields: string[];
  unknownFields: string[];
}

export interface StardewSaveSnapshot {
  plantingZones?: PlantingZoneSummary[];
}
```

设计说明：

- `unlockState` 表示解锁状态是否能从存档确认。
- `usable` 表示该地点是否具备可种植区域证据。姜岛已开放但岛屿农场区域未确认时，`unlockState='unlocked'`，`usable=false` 或 `undefined`。
- `emptyTilledTileCount` 只表示“已耕且无作物的空地”，不表示全部可种植格数。
- `sprinklerCoverageParsed=false` 时可以展示“检测到洒水器”，但不能声称空地已被覆盖。
- `plantingZones` 是新模型；`farmPlotSummary` 保留，用于兼容旧展示和旧测试。

### 3.2 普通农场兼容映射

解析完成后必须保证：

```ts
snapshot.farmPlotSummary === deriveFarmPlotSummaryFromZone(snapshot.plantingZones, 'farm')
```

兼容原则：

- 旧代码继续读取 `farmPlotSummary` 时行为不变。
- 新推荐逻辑优先读取 `plantingZones`。
- 如果 `plantingZones` 不存在，则从 `farmPlotSummary` 构造普通农场 fallback zone。

### 3.3 作物静态数据

扩展 `CropPlantingOption`：

```ts
export interface CropPlantingOption {
  id: string;
  name: string;
  season: Season;
  seasons?: Season[];
  daysToMature: number;
  growthDays: number;
  seedPrice: number;
  sellPrice: number;
  seedIds: Array<number | string>;
  seedName: string;
  regrowDays?: number;
  allowedPlantingZones?: PlantingZone[];
  disallowedPlantingZones?: PlantingZone[];
  specialRequirements?: string[];
  processingValueTags?: string[];
  notes?: string;
}
```

兼容规则：

- 旧数据只有 `season` 时，运行时转换为 `seasons=[season]`。
- 旧数据没有 `allowedPlantingZones` 时，默认只允许 `farm`，避免温室/姜岛规则误用不完整静态数据。
- 完成数据校准后，再把常规春夏秋作物显式标记为 `['farm', 'greenhouse', 'ginger_island_farm']`。

## 四、存档解析设计

### 4.1 解析入口

在 `src/stardew/saves/parseSave.ts` 增加：

```ts
function parsePlantingZones(root: XmlObject, farm: FarmSummary): PlantingZoneSummary[] {
  return [
    parseFarmPlantingZone(root),
    parseGreenhousePlantingZone(root),
    parseGingerIslandFarmPlantingZone(root, farm),
  ];
}
```

`parseSave` 组装 snapshot 时：

1. 先解析 `farm` 基础状态，包括姜岛访问状态。
2. 调用 `parsePlantingZones(root, farm)`。
3. 用普通农场 zone 派生 `farmPlotSummary`，保持旧字段兼容。

### 4.2 通用地点地块解析

抽取通用函数：

```ts
function parsePlantingZoneFromLocation(
  location: XmlObject | undefined,
  zone: PlantingZone,
  unlockState: PlantingZoneUnlockState,
  usable?: boolean,
): PlantingZoneSummary
```

解析内容：

- `terrainFeatures.item` 中的 HoeDirt 数量。
- HoeDirt 中带 `crop` 的数量。
- `crop.isReadyForHarvest` 为 true 的成熟作物数量。
- HoeDirt 且没有 `crop` 的已耕空地数量。
- `objects.item` 中洒水器数量。
- 字段存在性写入 `parsedFields`。
- 字段缺失或暂不支持的部分写入 `unknownFields`。

### 4.3 地点定位策略

普通农场：

- 继续定位 `GameLocation.name === 'Farm'`。
- `unlockState='unlocked'`，`usable=true`。
- 字段路径沿用 `locations.GameLocation[name=Farm]...`。

温室：

- 优先定位 `GameLocation.name === 'Greenhouse'`。
- 如果存在温室地点且能解析 terrainFeatures，则 `unlockState='unlocked'`，`usable=true`。
- 如果社区中心茶水间或 Joja 温室项目完成标记能确认温室修复，但地点对象缺失，则 `unlockState='unlocked'`，`usable=undefined`，并写入 `unknownFields=['greenhouseLocation']`。
- 如果能确认温室未修复，则 `unlockState='locked'`，`usable=false`。
- 不能确认时 `unlockState='unknown'`，不生成温室专项推荐。

姜岛农场：

- `farm.hasIslandAccess === false` 时，`unlockState='locked'`，`usable=false`。
- `farm.hasIslandAccess === true` 时，继续查找岛屿农场地点。
- 地点名称候选建议由静态规则配置提供，初始候选包括 `IslandWest`、`IslandFarm`、`GingerIslandFarm`。
- 找到可解析 terrainFeatures 的岛屿农场地点时，`unlockState='unlocked'`，`usable=true`。
- 只确认姜岛开放但找不到农场地点时，`unlockState='unlocked'`，`usable=undefined`，写入 `unknownFields=['gingerIslandFarmLocation']`，不生成强种植建议。

### 4.4 解锁状态来源

温室解锁来源优先级：

1. 明确存在可用 `Greenhouse` 地点和地块字段。
2. Joja `greenhouse` 项目完成标记。
3. 社区中心茶水间完成标记。
4. 存档 mail / events 中可稳定识别的温室修复标记。
5. 无法确认。

姜岛农场来源优先级：

1. 岛屿农场地点存在且可解析。
2. `hasIslandAccess` 与岛屿农场相关标记同时存在。
3. 仅 `hasIslandAccess` 存在时，只作为姜岛开放，不作为农场可用。

## 五、推荐引擎设计

### 5.1 函数拆分

将现有 `buildPlantingActions` 拆分为：

```ts
function buildPlantingActions(input: PlannerInput): RecommendationItem[] {
  return [
    ...buildZonePlantingActions(input, 'farm'),
    ...buildZonePlantingActions(input, 'greenhouse'),
    ...buildZonePlantingActions(input, 'ginger_island_farm'),
  ];
}
```

核心函数：

```ts
function buildZonePlantingActions(
  input: PlannerInput,
  zone: PlantingZone,
): RecommendationItem[]
```

职责：

- 获取对应 `PlantingZoneSummary`。
- 按地块解锁和可用状态决定是否生成候选。
- 按地块类型过滤作物。
- 生成带地块语义的标题、证据、不确定项和估算。

### 5.2 作物过滤

普通农场：

```ts
crop.seasons.includes(input.planDate.season)
  && crop.growthDays <= 28 - input.planDate.day
  && crop.allowedPlantingZones.includes('farm')
```

温室：

```ts
crop.allowedPlantingZones.includes('greenhouse')
  && crop.seasons.some((season) => season !== 'winter')
```

姜岛农场：

```ts
crop.allowedPlantingZones.includes('ginger_island_farm')
  && crop.seasons.some((season) => season !== 'winter')
```

特殊规则：

- `disallowedPlantingZones` 命中目标 zone 时直接过滤。
- `specialRequirements` 中含未支持规则时，候选可保留但置信度最高为中，并展示“特殊种植规则未完全解析”。
- 金币不足且无已有种子时，不生成购买型强建议。

### 5.3 收益与成熟计算

新增计算函数：

```ts
function calculateZoneCropRoi(
  crop: CropPlantingOption,
  date: CropPlantingDate,
  zone: PlantingZone,
): CropRoiEstimate
```

规则：

- `farm` 继续使用季末前成熟逻辑。
- `greenhouse` 和 `ginger_island_farm` 不使用当季第 28 天作为硬截止。
- 对温室/姜岛农场，单次作物至少展示首次成熟天数；复收作物展示长期收益，不承诺固定季末总收益。
- 温室/姜岛农场的 `estimate.kind` 建议使用 `projected`，描述使用“首次成熟后可持续复收”或“首次成熟后可收获一次”。

### 5.4 证据生成

新增：

```ts
function createPlantingZoneEvidence(
  input: PlannerInput,
  zoneSummary: PlantingZoneSummary,
  crop: CropPlantingOption,
): RecommendationItem['evidence']
```

证据字段：

- 推荐地块。
- 地块状态。
- 作物季节。
- 生长天数。
- 预计收获次数或长期收益说明。
- 当前金币。
- 已有种子。
- 商店或购买状态。
- 对应地块空地。
- 对应地块洒水条件。

证据约束：

- 温室建议只能读取 `zone='greenhouse'` 的空地和洒水器。
- 姜岛农场建议只能读取 `zone='ginger_island_farm'` 的空地和洒水器。
- 普通农场建议继续读取 `zone='farm'` 或兼容 `farmPlotSummary`。

### 5.5 不确定项与置信度

新增：

```ts
function buildZonePlantingUncertainty(status: {
  zone: PlantingZone;
  unlockState: PlantingZoneUnlockState;
  usable?: boolean;
  hasSeed: boolean;
  canBuySeed: boolean;
  hasParsedEmptyPlots: boolean;
  hasParsedSprinklerCoverage: boolean;
  hasCompleteCropZoneRule: boolean;
}): string[]
```

置信度规则：

- 地块未解锁或无法确认：不生成专项建议。
- 地块已解锁但 `usable !== true`：不生成强行动；如需要，只在探索进度展示待确认。
- 空地或洒水覆盖未解析：最高中。
- 种子不可购买且库存无种子：不生成购买型建议。
- 作物地块规则不完整：最高中。
- 同时具备地块可用、空地明确、种子/购买明确、洒水覆盖明确、作物地块规则完整时，才允许高置信。

## 八、实施顺序

### 阶段 1：数据模型和兼容层

1. 在 `src/shared/types.ts` 新增 `PlantingZone`、`PlantingZoneSummary`。
2. 在 `parseSave.ts` 中新增 `plantingZones` 字段。
3. 从普通农场 zone 派生旧 `farmPlotSummary`，保证现有测试不需要一次性重写。
4. 补基础类型测试和普通农场兼容测试。

### 阶段 2：地点解析

1. 抽取通用 `parsePlantingZoneFromLocation`。
2. 接入 `Farm`、`Greenhouse`、姜岛农场地点候选。
3. 增加温室和姜岛农场解锁状态判定。

1. 扩展 `CropPlantingOption` 类型。
2. 为现有作物数据补 `seasons` 和 `allowedPlantingZones`。
3. 常规春夏秋作物先覆盖温室和姜岛农场。

1. 拆分 `buildPlantingActions` 为按 zone 生成。
2. 为普通农场保留季末成熟过滤。
3. 为温室/姜岛农场增加无季末硬截止的候选规则。
4. 补推荐证据、不确定项和置信度规则。
5. 补排序规则，确保已有种子和明确空地优先。

### 阶段 5：展示和国际化

1. 补 recommendation localization。
2. 补探索进度地块状态展示。
3. 扩展中英文泄漏测试。
4. 确认详情弹窗和推荐卡片不出现裸英文/裸中文。

## 九、风险与降级策略

| 风险 | 技术表现 | 降级策略 |
|---|---|---|
| 温室修复标记不稳定 | 无法确认 `Greenhouse` 是否可用 | 不生成温室专项推荐，只在探索进度显示状态待确认 |
| 姜岛开放不等于农场可用 | `hasIslandAccess=true` 但找不到岛屿农场地点 | 不生成姜岛农场强建议 |
| 地点名称跨版本变化 | `IslandWest` 等名称匹配失败 | 地点候选放入静态规则，缺失时 unknownFields 说明 |
| 作物规则不完整 | 作物缺少 allowedPlantingZones | 默认只允许普通农场，温室/姜岛建议降级或不生成 |
| 洒水覆盖无法精确 | 只能识别洒水器数量 | 只展示检测到洒水器，置信度最高中 |
| UI 文案泄漏 | 新增地块名未翻译 | i18nRuntimeScan 覆盖标题、证据、不确定项 |

## 十一、发布关系

本方案对应 1.1.0 主需求中的 P2 “更完整的温室/姜岛农场种植规则”。

处理原则：

1. 未实现本方案不阻断 1.1.0 可发布版本。
2. 如需拆分交付，优先上线温室解析和温室专项推荐。
3. 姜岛农场必须在 fixture 能稳定证明“农场区域可用”后再生成强建议。
4. 每一步都必须保持普通农场推荐回归稳定。
