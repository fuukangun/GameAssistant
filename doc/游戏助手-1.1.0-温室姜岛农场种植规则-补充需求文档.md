# 游戏助手 1.1.0 - 温室/姜岛农场种植规则补充需求文档

> **版本**: v1.0  
> **日期**: 2026-06-28  
> **关联文档**: [游戏助手-1.1.0-需求文档.md](./游戏助手-1.1.0-需求文档.md)  
> **关联技术设计**: [游戏助手-1.1.0-技术设计.md](./游戏助手-1.1.0-技术设计.md)  
> **主题**: 温室与姜岛农场种植推荐可信度增强  
> **范围定位**: 1.1.0 P2 可延期能力的补充需求，不改变 1.1.0 P0/P1 交付边界

---

## 一、背景

当前 1.1.0 种植推荐主要按普通农场逻辑处理：

- 作物必须匹配当前季节。
- 普通单季作物必须能在当季第 28 天前成熟。
- 空地和洒水器覆盖解析不完整时，种植建议降级并展示不确定项。

该策略对普通室外农场是安全的，但对温室和姜岛农场偏保守：

- 温室可全年种植多数常规作物，不受本土季节限制。
- 姜岛农场可全年种植多数常规作物，不受本土季节限制。
- 温室和姜岛农场的可种植空间、洒水覆盖、已种作物状态与普通农场不同，不能简单复用普通农场空地证据。

因此需要补充一套独立的温室/姜岛农场种植规则，让 App 在能解析到明确证据时给出更有价值的推荐，在证据不足时继续保持保守。

---

## 二、目标

### 2.1 产品目标

1. 温室或姜岛农场已解锁时，避免因当前本土季节不匹配而遗漏合理种植建议。
2. 普通农场、温室、姜岛农场的种植建议必须明确标注适用地块。
3. 若无法确认温室或姜岛农场是否可用，不得输出“全年可种”的强建议。
4. 若无法确认温室/姜岛农场空地或洒水覆盖，只能输出中低置信建议并展示不确定项。
5. 中英文模式下地块名称、作物名称、原因、证据和不确定项必须完整国际化。

### 2.2 非目标

- 不写回或修改存档。
- 不接入 SMAPI 实时 Mod。
- 不读取游戏运行时内存。
- 不承诺精确计算温室或姜岛农场全部可种植格数，除非存档字段可以稳定支持。
- 不实现全量作物百科和最优 ROI 求解器。
- 不自动联网同步 Wiki 数据。
- 不把温室/姜岛农场能力作为 1.1.0 P0 发布阻断项。

## 三、核心规则

### 3.1 地块类型

种植推荐必须区分以下地块类型：

| 地块类型 | 季节限制 | 解锁条件 | 推荐前提 |
|---|---|---|---|
| 普通农场 | 受当前本土季节限制 | 默认可用 | 当前季节匹配，且能在季末前成熟 |
| 温室 | 不受当前本土季节限制 | 温室已修复或等价存档标记已确认 | 温室可用，且有可种植空间或用户可自行调整 |
| 姜岛农场 | 不受当前本土季节限制 | 姜岛已开放，且岛屿农场区域可用 | 姜岛农场可用，且有可种植空间或用户可自行调整 |

### 3.2 作物适用规则

1. 普通农场：
   - 只推荐当前季节可种作物。
   - 单季作物必须满足 `计划日 + 生长天数 <= 当季第 28 天`。
   - 跨季作物按其支持季节保守计算。

2. 温室：
   - 可推荐春、夏、秋的常规作物。
   - 不因本土季节结束而过滤作物。
   - 多次收获作物可展示长期收益优势。
   - 若作物存在特殊地块限制或不能在温室种植，必须从候选中排除。

3. 姜岛农场：
   - 可推荐春、夏、秋的常规作物。
   - 不因本土季节结束而过滤作物。
   - 可优先推荐高价值、多次收获或加工价值高的作物。
   - 若作物存在特殊地块限制或不能在姜岛农场种植，必须从候选中排除。

4. 冬季：
   - 普通农场不推荐常规春夏秋作物。
   - 温室和姜岛农场已确认可用时，仍可推荐可种作物。

### 3.3 候选作物分类

静态作物数据需要补充地块适用能力：

| 字段 | 说明 |
|---|---|
| `seasons` | 作物在普通农场适用的季节列表 |
| `growthDays` | 首次成熟天数 |
| `regrowDays` | 复收间隔，没有则为空 |
| `seedIds` | 种子 itemId |
| `seedPrice` | 常规购买价格 |
| `sellPrice` | 普通品质基础售价 |
| `allowedPlantingZones` | 可种地块：普通农场、温室、姜岛农场 |
| `disallowedPlantingZones` | 明确不可种地块 |
| `specialRequirements` | 特殊限制，例如树苗、棚架、稻田、巨大作物等 |
| `processingValueTags` | 加工价值标签，例如酿酒、果酱、脱水、腌制 |

## 四、存档解析需求

### 4.1 温室状态

需要解析并输出：

- 温室是否已修复。
- 温室位置是否存在可解析的地块对象。
- 温室内已种植作物数量。
- 温室内成熟作物数量。
- 温室内已耕空地数量。
- 温室内洒水器数量。
- 温室洒水覆盖是否已解析。
- 未解析字段列表。

解析规则：

- 能稳定确认温室已修复时，才允许生成温室专项种植建议。
- 仅能确认温室修复、不能确认空地时，可以生成中置信建议，但必须提示“温室空地未精确解析”。
- 不能确认温室修复时，不生成温室专项种植建议。

### 4.2 姜岛农场状态

需要解析并输出：

- 姜岛是否已开放。
- 姜岛农场区域是否可用。
- 姜岛农场已种植作物数量。
- 姜岛农场成熟作物数量。
- 姜岛农场已耕空地数量。
- 姜岛农场洒水器数量。
- 姜岛农场洒水覆盖是否已解析。
- 未解析字段列表。

解析规则：

- 仅有“姜岛已开放”不等于“姜岛农场可种植区域已可用”。
- 能确认姜岛农场区域可用时，才允许生成姜岛农场专项种植建议。
- 只能确认姜岛开放、不能确认农场区域时，不生成强建议，只能在探索进度中显示待确认。

### 4.3 数据模型要求

建议在现有 `farmPlotSummary` 之外增加按地点聚合的种植地块摘要：

```ts
type PlantingZone = 'farm' | 'greenhouse' | 'ginger_island_farm';

interface PlantingZoneSummary {
  zone: PlantingZone;
  unlocked: boolean;
  usable?: boolean;
  plantedCropCount?: number;
  matureCropCount?: number;
  tilledTileCount?: number;
  emptyTilledTileCount?: number;
  sprinklerCount?: number;
  sprinklerCoverageParsed?: boolean;
  parsedFields: string[];
  unknownFields: string[];
}
```

要求：

- 普通农场、温室、姜岛农场不能混在同一个空地计数中。
- 推荐证据必须写明地块来源，例如“温室已耕空地 8 块”。
- 不确定项必须写明具体地块，例如“姜岛农场洒水覆盖未解析”。

## 五、推荐生成需求

### 5.1 推荐类型

新增或扩展以下推荐类型：

1. 普通农场种植建议。
2. 温室种植建议。
3. 姜岛农场种植建议。
4. 温室/姜岛成熟作物收获提醒。
5. 温室/姜岛长期作物维护提醒。

### 5.2 推荐证据

温室和姜岛农场种植建议必须展示：

- 推荐地块：温室或姜岛农场。
- 作物名称。
- 生长天数。
- 预计首次成熟日期或天数。
- 预计收获次数。
- 当前金币。
- 是否已有种子。
- 是否可购买种子。
- 是否检测到对应地块可用。
- 是否检测到对应地块空地。
- 是否检测到对应地块洒水器。
- 洒水覆盖是否已解析。
- 推荐原因。

### 5.3 置信度规则

| 场景 | 最高置信度 |
|---|---|
| 地块已解锁、可用、空地明确、种子/金币明确、洒水覆盖明确 | 高 |
| 地块已解锁且可用，但空地或洒水覆盖未解析 | 中 |
| 仅确认温室或姜岛开放，但无法确认对应地块可用 | 低，不生成强行动 |
| 无法确认地块解锁状态 | 不生成专项种植建议 |
| 作物静态数据缺少地块适用规则 | 中，且展示数据缺口 |
| 作物明确不适用于目标地块 | 不生成建议 |

### 5.4 排序规则

排序建议：

1. 已有种子且目标地块有明确空地的建议优先。
2. 多次收获作物优先于单次低收益作物。
3. 可衔接加工链的作物优先，例如水果、小桶、罐头瓶相关作物。
4. 当前金币不足时，不生成购买型强建议，只能提示材料或资金缺口。
5. 普通农场临近季末时，温室/姜岛农场建议可高于普通农场种植建议。

## 六、页面与交互要求

### 6.1 推荐行动卡片

推荐标题必须带地块语义：

- `温室可以种植蓝莓`
- `姜岛农场可以种植杨桃`
- `普通农场可以种植防风草`

推荐理由必须避免模糊表述：

- 正确：`温室不受当前季节限制，蓝莓可复收，适合作为长期作物。`
- 错误：`当前季节适合种蓝莓。`

### 6.2 证据展示

证据字段示例：

| 标签 | 示例 |
|---|---|
| 推荐地块 | 温室 |
| 地块状态 | 已修复 |
| 作物季节 | 夏季 |
| 生长天数 | 13 天 |
| 预计收获次数 | 复收作物，长期收益 |
| 已有种子 | 蓝莓种子 x12（储物箱） |
| 可用空地 | 温室已耕空地 8 块 |
| 洒水条件 | 温室检测到铱制洒水器 2 个 |

### 6.3 探索进度

探索进度可补充显示：

- 温室：未修复 / 已修复 / 状态待确认。
- 姜岛农场：未开放 / 已开放但农场待确认 / 可用 / 状态待确认。
- 温室作物摘要。
- 姜岛农场作物摘要。

## 七、国际化要求

必须覆盖以下文本：

- 温室。
- 姜岛农场。
- 普通农场。
- 地块状态。
- 空地证据。
- 洒水覆盖。
- 作物适用地块。
- 温室不受季节限制。
- 姜岛农场不受季节限制。
- 温室空地未精确解析。
- 姜岛农场区域未确认。

验收要求：

- 中文模式不得出现 `Greenhouse`、`Ginger Island Farm` 等可翻译英文。
- 英文模式不得出现 `温室`、`姜岛农场` 等中文。
- 推荐标题、原因、证据、不确定项和详情弹窗均需覆盖。

## 八、验收标准

### 8.1 功能验收

1. 普通农场仍遵守当前季节和季末成熟限制。
2. 温室已修复时，冬季也可以生成温室种植建议。
3. 姜岛农场可用时，冬季也可以生成姜岛农场种植建议。
4. 温室建议不会引用普通农场空地作为证据。
5. 姜岛农场建议不会引用普通农场或温室空地作为证据。
6. 地块不可确认时，不生成高置信种植建议。
7. 作物明确不适用于目标地块时，不生成建议。
8. 种子、金币、空地、洒水覆盖任一关键项缺失时，建议必须展示不确定项。

### 8.2 回归验收

1. 春、夏、秋普通农场种植推荐不被温室/姜岛规则破坏。
2. 春 25-28 日普通农场仍不推荐无法成熟的单季作物。
3. 温室/姜岛建议不影响钓鱼、加工、下矿、社区中心、Joja 推荐生成。
4. 未开放姜岛的存档不出现姜岛农场种植建议。
5. 未修复温室的存档不出现温室种植建议。

### 8.3 Fixture 建议

建议补充以下脱敏 fixture：

| Fixture | 用途 |
|---|---|
| `greenhouse-locked` | 温室未修复，不生成温室种植建议 |
| `greenhouse-ready-winter` | 冬季温室已修复，可推荐温室作物 |
| `greenhouse-no-empty-plot` | 温室无明确空地，建议降级 |
| `island-open-farm-unknown` | 姜岛开放但农场区域未确认，不生成强建议 |
| `island-farm-ready-winter` | 冬季姜岛农场可用，可推荐作物 |
| `multi-zone-late-season` | 普通农场季末过滤，温室/姜岛仍可推荐 |

## 九、优先级建议

### P0

- 不进入 1.1.0 P0。

### P1

- 若 1.1.0 发布前已有可靠 fixture，可先补温室已修复状态和温室专项推荐。

### P2

1. 姜岛农场区域可用性解析。
2. 按地点聚合的空地和洒水器解析。
3. 温室/姜岛专项种植推荐。
4. 作物地块适用静态表。
5. 温室/姜岛专项国际化泄漏测试。

## 十、风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 存档字段不稳定 | 温室和姜岛农场在不同版本、平台、Mod 下字段可能不同 | 使用脱敏 fixture 校准，字段不明确时降级 |
| 推荐过度自信 | 只确认姜岛开放不代表姜岛农场已可用 | 解锁状态和地块可用性分开建模 |
| 空地证据混用 | 普通农场空地被误用于温室/姜岛 | 按地点聚合地块摘要，推荐证据必须带地块 |
| 静态作物表不完整 | 特殊作物、树苗、巨大作物规则复杂 | 先覆盖常规作物，特殊规则缺失时降级 |
| 国际化遗漏 | 新增地块和不确定项文案容易漏翻译 | 增加推荐标题、证据、不确定项泄漏测试 |

## 十一、发布关系

本补充需求是 1.1.0 主需求中“更完整的温室/姜岛农场种植规则”的细化说明。

建议处理方式：

1. 1.1.0 可发布版本不因本需求未完成而阻断。
2. 若发布前时间允许，优先实现温室已修复状态解析和温室专项推荐。
3. 姜岛农场规则建议在有可靠 fixture 后再实现，避免仅凭“姜岛已开放”输出过度自信建议。
4. 后续实现时必须先补解析和 fixture，再接入推荐排序。
