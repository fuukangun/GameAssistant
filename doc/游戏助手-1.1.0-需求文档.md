# 游戏助手 1.1.0 - 产品需求文档

> **版本**: v1.0  
> **日期**: 2026-06-27  
> **基线版本**: 1.0.1  
> **目标版本**: 1.1.0  
> **主题**: 推荐可信度增强  
> **核心原则**: 不改核心页面样式，优先提升解析准确度、推荐可信度、国际化完整度和发布稳定性

---

## 一、背景

游戏助手 1.0.1 已完成可发布版本，当前能力包括：

- 自动扫描《星露谷物语》存档，支持手动选择存档文件夹导入。
- 解析睡觉后存档中的日期、天气、库存、技能、装备、路线进度、地图解锁、矿洞/骷髅洞穴、社区中心、Joja、NPC 好感、机器产物、动物产物、干草等字段。
- 生成重要提醒、推荐行动、角色技能、友谊维系、探索进度等视图。
- 推荐行动已覆盖生日、节日、季末风险、动物饲料、收获、加工、钓鱼、种植、社区中心交付、Joja 项目、矿洞推进、工具升级、农场维护。
- 已支持中文/英文界面、物品图标、全局库存、礼物匹配、GitHub Actions 打包。
- 1.0.1 已修复大库存友谊页卡顿、存档切换后 tab 未重置、版本元数据和 DMG 后置脚本版本硬编码问题。

1.1.0 不再解决“能不能用”的问题，而是解决“推荐是否足够可信”的问题。

---

## 二、版本目标

### 2.1 产品目标

1. 降低推荐行动中的不确定项比例。
2. 让农业、加工、钓鱼、下矿、升级、社区中心/Joja 相关建议具备更明确的数据依据。
3. 避免在存档证据不足时输出强建议。
4. 保持现有首页、角色技能、友谊维系、探索进度页面结构稳定，只做数据校准和必要文案修正。
5. 提高中英文国际化和 release 构建稳定性。

### 2.2 目标用户

| 用户类型 | 1.1.0 重点收益 |
|---|---|
| 普通玩家 | 推荐行动更少误导，能明确知道今天优先做什么 |
| 效率玩家 | 赚钱、种植、加工、钓鱼、下矿建议更可信 |
| 后期多箱子玩家 | 大库存性能稳定，礼物/加工/社区中心匹配更可靠 |
| 发布使用者 | macOS/Windows 安装包命名、版本元数据、release 流程更稳定 |

---

## 三、范围约束

### 3.1 本期做

- 推荐行动可信度增强。
- 存档解析补强。
- 静态规则数据继续外置和校验。
- 国际化全量收口。
- 发布工程增强。

### 3.2 本期不做

- 不新增泰拉瑞亚或其他游戏支持。
- 不做 SMAPI 实时 Mod。
- 不读取游戏运行时内存。
- 不写回或修改存档。
- 不大改首页、角色技能、友谊维系、探索进度页面样式。
- 不恢复“拥有物品”tab 的默认展示。
- 不做多人存档完整支持，只保留检测和降级提示。
- 不自动联网同步 Wiki 数据。

## 四、功能需求

## 4.1 推荐行动可信度增强

### 4.1.1 农业推荐

现状：

- 已支持季末最后 4 天提醒不要种植无法成熟的单季节作物。
- 已能基于作物静态数据、金币、已有种子、商店开放、空地摘要、洒水器存在性生成种植建议。
- 空地解析仍偏保守，洒水器覆盖没有精确到地块。

1.1.0 需求：

- 种植推荐必须同时展示以下依据：
  - 作物名称。
  - 生长天数。
  - 距离季末剩余天数。
  - 预计收获次数。
  - 当前金币。
  - 是否已有种子。
  - 是否检测到可用已耕空地。
  - 是否检测到洒水器。
- 若无法确认空地，不能输出“可种 N 格”这类强结论。
- 若无法确认洒水覆盖，只能说明“检测到洒水器”，不能声称“无需浇水”或“这些地块已被覆盖”。
- 如果无空地或空地未解析，种植建议置信度最高为中。
- 如果只检测到洒水器存在，但不能确认洒水器覆盖目标地块，种植建议置信度最高为中。
- 若季末无法成熟，不得生成种植推荐，只能生成风险提醒。

验收标准：

- 第 25-28 天不会推荐无法成熟的单季节作物。
- 有种子、有金币、有已解析空地，且洒水器覆盖关系可确认时，推荐置信度可为高。
- 缺少空地或洒水证据时，推荐中必须说明未解析项。

### 4.1.2 加工推荐

现状：

- 已支持收取 readyMachineOutputs。
- 已支持基于 Processing Rules 推荐鱼熏制、酿酒、罐头、蛋黄酱、奶酪等加工。
- 当前仍存在“机器当前占用状态尚未解析”等不确定项。

1.1.0 需求：

- 加工推荐分为两类：
  - 收取加工产物：来自存档中已完成机器产物。
  - 安排新加工：来自库存原料 + 已拥有机器 + 规则数据。
- 收取加工产物必须按来源聚合，同一来源下相同物品合并数量。
- 安排新加工必须展示：
  - 已拥有机器。
  - 可用原料及来源。
  - 预期产物。
  - 是否缺少辅助材料，例如煤炭。
  - 机器占用状态是否已解析。
- 若没有机器但有高价值原料，应生成“补齐加工设备”建议，而不是直接建议加工。
- 若机器占用无法确认，置信度最高为中。

验收标准：

- Vanilla 这类后期存档不会在推荐卡片中显示过长产物列表，超过阈值必须进入详情弹窗。
- 详情按来源折叠，同一分组相同物品聚合为 `物品 xN`。
- 中文模式下来源和物品名不得出现裸英文。

### 4.1.3 钓鱼推荐

现状：

- 已有鱼类百科目录和按季节、天气、地点、时间、地图解锁的筛选能力。
- 钓鱼推荐仍可能提示“可达水域、鱼类时间窗口未解析”。

1.1.0 需求：

- 钓鱼推荐必须基于以下信息：
  - 是否拥有鱼竿。
  - 鱼竿名称。
  - 是否有鱼饵。
  - 今日季节。
  - 今日天气。
  - 地图解锁：沙漠、姜岛、矿洞层数。
  - 今日可钓鱼类列表。
- 未拥有鱼竿时，不得推荐“钓鱼赚钱”，应推荐“先获取鱼竿”。
- 有鱼竿但无鱼饵时，可以推荐钓鱼，但必须说明无鱼饵影响效率。
- 可钓鱼类为空时，收益估算置信度为低。
- 可钓鱼类不为空时，收益估算置信度至少为中。

验收标准：

- fun 存档未拥有鱼竿时，推荐“先获取鱼竿”排在钓鱼赚钱前。
- 英文模式下钓鱼推荐不得出现中文鱼名、中文地点或中文时间窗口。
- 中文模式下钓鱼推荐不得出现英文鱼名，除非该物品确实无中文目录数据。

### 4.1.4 下矿与骷髅洞穴推荐

现状：

- 已解析普通矿洞与骷髅洞穴层数。
- 已支持食物、武器、炸弹、楼梯等下矿准备规则。
- 普通矿洞必须封顶 120 层，骷髅洞穴不封顶。
- 当前普通矿洞已有推进建议，骷髅洞穴以进度展示和字段校准为主，尚未形成独立评分推荐系统。

1.1.0 需求：

- 普通矿洞推荐目标不得超过 120 层。
- 骷髅洞穴推荐应使用独立字段，不得复用普通矿洞层数。
- 普通矿洞推进建议必须展示：
  - 当前普通矿洞层数或骷髅洞穴层数。
  - 生命值。
  - 武器状态。
  - 食物状态。
  - 炸弹/楼梯状态。
  - 今日运势等级，不展示具体 dailyLuck 数值。
- 若缺少武器或食物，矿洞推进建议必须降级。
- 若生命过低，下矿建议必须说明风险。
- 骷髅洞穴 1.1.0 只要求层数和开放状态解析准确；独立的骷髅洞穴收益/冲层评分规则不作为 P0 交付。

验收标准：

- Moja Joja 等存档中普通矿洞层数不超过 120。
- 骷髅洞穴显示“最深 N 层”，未开放时显示“未开放”。
- 下矿建议不输出具体运气数值。

### 4.1.5 装备升级推荐

现状：

- 已有 upgradeRules.json，能根据库存材料和金币推荐背包/工具升级。
- 铁匠铺是否已有工具在升级仍未解析。

1.1.0 需求：

- 升级推荐必须区分：
  - 背包升级。
  - 工具升级。
- 工具升级必须展示：
  - 当前工具等级。
  - 下一等级。
  - 所需材料。
  - 所需金币。
  - 玩家库存是否满足。
  - 铁匠铺占用状态是否已解析。
- 如果无法确认铁匠铺是否正在升级工具，工具升级建议置信度最高为中。
- 如果当天是雨天或作物浇水压力低，喷壶升级建议可提高排序。

验收标准：

- 材料不足时不生成强升级建议。
- 工具升级建议包含“不确定项：铁匠铺是否正在处理其他工具尚未解析”或等价文案。

## 4.2 存档解析增强

### 4.2.1 机器状态解析

目标：

- 在现有 readyMachineOutputs 基础上，增强机器状态模型。
- 本期采用保守解析策略：只有存档字段语义明确时才标记为空闲或占用；无法稳定判断时必须标记为“无法解析”，不得猜测。
- 区分以下状态：
  - 已完成，有产物可收取。
  - 正在加工，占用中。
  - 空闲，可安排新加工。
  - 无法解析。

涉及设备：

- 小桶。
- 罐头瓶。
- 熔炉。
- 鱼熏制机。
- 蛋黄酱机。
- 奶酪压制机。
- 脱水机。
- 树液采集器。

验收标准：

- 已完成产物进入“收取加工产物”。
- 空闲机器可作为“安排新加工”的高置信依据。
- 占用中机器不得被重复用于新加工建议。
- 无法解析的机器不得作为高置信“安排新加工”依据，只能让对应建议降级并展示不确定项。

### 4.2.2 动物与饲料解析

目标：

- 在现有 animalProducts 和 animalFeed 基础上继续增强：
  - 动物数量。
  - 干草数量。
  - 可支撑天数。
  - 秋季末风险。
  - 自动采集器产物。
  - 动物今日产物是否可收取。

验收标准：

- 干草不足 2 天时生成重要提醒。
- 秋季第 25-28 天且干草不足时，提醒升级为必做。
- 动物产物详情中物品名和来源国际化完整。

### 4.2.3 农场地块解析

目标：

- 保守解析农场地块，不承诺完整地图建模。
- 输出：
  - 已种植作物数量。
  - 已耕地数量。
  - 已耕空地数量。
  - 资源障碍物数量。
  - 建筑数量。
  - 解析字段列表。
  - 未解析字段列表。

验收标准：

- 有已耕空地证据时，种植推荐可引用。
- 没有可靠空地证据时，不输出精确空地数量。
- 农场地块解析失败不能影响存档基础解析。

### 4.2.4 社区中心 Bundle 校准与回归

现状：

- 已有 communityCenterBundles.json。
- 已能计算总体进度、房间/收集包进度和可交付物品详情。
- 已按存档中的收集包完成标记过滤已完成收集包。
- 已能在库存存在可交付物品时生成“去社区中心交付库存物品”推荐行动。
- 推荐行动详情已按房间和收集包分类展示。
- 已完成社区中心、Joja 路线、未知路线均不会生成社区中心交付建议。

1.1.0 范围：

- 不重做社区中心推荐主流程。
- 校准真实存档脱敏 fixture 中 bundleStates / donatedSlots 等字段语义，确认“已完成”和“已交付槽位”的判断不误伤。
- 补充脱敏 fixture 回归用例，覆盖社区中心中期、社区中心全完成、Joja 路线、未确认路线。
- 继续校验详情中的物品图标和中英文名称完整性。

验收标准：

- 社区中心全完成存档进度为 100%，不出现“去社区中心交付库存物品”。
- 社区中心中期存档只推荐未完成且库存可满足的项。
- Joja 路线和未确认路线不出现社区中心交付建议。
- 详情中每个物品带图标和本地化名称。

### 4.2.5 Joja 路线校准与回归

现状：

- 已能解析 Joja 路线。
- 已能展示 Joja 项目列表、已购买/未购买状态和项目价格。
- 已能根据已完成项目标记或已完成数量推断下一个项目。
- 已能根据当前金币生成“可购买项目”或“还差 N 金”的推荐行动。
- 社区中心路线不会生成 Joja 资金建议。

1.1.0 范围：

- 不重做 Joja 路线推荐主流程。
- 校准 Joja 脱敏 fixture 中的项目完成标记，确认 completedMarkers 和 completedProjects 的优先级正确。
- 补充 Joja 中期、Joja 全完成、社区中心路线的脱敏 fixture 回归用例。
- 继续校验 Joja 项目名称、推荐理由、证据字段的中英文国际化。

验收标准：

- Joja 全完成存档不生成 Joja 购买建议。
- Joja 中期存档根据金币生成“可购买项目”或“还差 N 金”建议。
- 社区中心路线不展示 Joja 资金建议。
- Joja 项目名称、金额和完成状态在中英文模式下均正确展示。

## 4.3 规则数据与校验

### 4.3.1 静态数据外置化

现状：

- 大量规则已 JSON 化，包括鱼类、NPC 礼物、物品目录、加工规则、升级规则、社区中心、Joja、日历、国际化等。
- 仍存在少量运行时常量和文案在 TypeScript 中。

1.1.0 需求：

- 新增规则数据覆盖报告，至少统计：
  - itemCatalog 覆盖数量。
  - itemIconIds 覆盖数量。
  - NPC 礼物偏好覆盖 NPC 数。
  - 鱼类规则数量。
  - 加工规则数量。
  - 升级规则数量。
  - 推荐国际化映射数量。
- 数据校验必须覆盖：
  - 礼物偏好 itemId 能在 itemCatalog 找到。
  - 推荐详情涉及 itemId 有图标。
  - 加工规则中的机器和原料能解析名称。
  - 升级规则中的材料能解析名称。
  - 中英文推荐文案不混用。

验收标准：

- `npm test` 能暴露新增数据缺口。
- 数据损坏时 App 不崩溃，相关建议降级或隐藏。

### 4.3.2 国际化完整性

目标：

- 中文模式不出现裸英文物品名、来源名、机器名、NPC 礼物名。
- 英文模式不出现中文物品名、来源名、机器名、鱼名。
- 重点覆盖：
  - 重要提醒。
  - 推荐行动。
  - 推荐详情弹窗。
  - 可送礼物弹窗。
  - 社区中心交付详情。
  - 加工产物详情。
  - 动物产物详情。
  - 探索进度。

验收标准：

- 使用仓库内脱敏 fixture 覆盖：Vanilla、菌菇、Moja Joja、Fazenda Á、fun 这 5 类代表性存档场景。
- CI 中的国际化泄漏测试只能依赖仓库内 fixture，不得依赖 `/Users/...` 等本机真实存档路径。
- 本机真实存档扫描可以作为 local-only 辅助校验，但不得作为 GitHub Actions 发布阻断条件。
- 中英文泄漏测试失败时阻断发布。

## 4.4 性能与交互稳定性

### 4.4.1 大库存性能

现状：

- 1.0.1 已优化友谊维系 tab，避免每次渲染重复扫描全量库存。

1.1.0 需求：

- 继续检查以下路径是否存在全量重复计算：
  - 推荐行动详情。
  - 社区中心可交付项。
  - 加工产物详情。
  - 友谊礼物弹窗。
  - 探索进度。
- 大库存存档切换 tab 时不应出现明显卡顿。

验收标准：

- Vanilla 存档切换到友谊维系、推荐行动详情、社区中心详情时交互无明显阻塞。
- 相同存档切换 tab 不重复解析 XML。
- 存档 A/B 切换后 tab 必须重置到重要提醒。

### 4.4.2 存档缓存与刷新

现状：

- App 运行期间已缓存已解析 snapshot。
- 切换已缓存存档不会重新读取 XML。

1.1.0 需求：

- 增加“刷新当前存档”能力或等价机制。
- 刷新只重新读取当前选中存档，不重新扫描所有存档。
- 如果文件不存在或移动，移除此手动导入记录并更新存档数量。

验收标准：

- 游戏内存档更新后，用户可以手动刷新当前存档。
- 刷新失败时显示明确错误，不保留失效路径。

## 4.5 发布工程

### 4.5.1 版本元数据

要求：

- 每次版本发布必须同步：
  - package.json。
  - package-lock.json。
  - src-tauri/Cargo.toml。
  - src-tauri/Cargo.lock。
  - src-tauri/tauri.conf.json。
  - About 元数据。

About 元数据格式：

## 七、验收标准汇总

### 7.1 功能验收

- 农业、加工、钓鱼、下矿、升级、社区中心、Joja 推荐均有明确数据依据。
- 使用 5 类代表性 fixture 统计推荐行动不确定项：P0 推荐中不得再出现已可解析字段导致的“未解析可达水域、鱼类时间窗口、机器占用状态、普通矿洞/骷髅洞穴层数混用”等问题。
- 对确实无法从睡觉后存档稳定解析的字段，必须保留不确定项，并将相关建议置信度限制为中或低。
- 无鱼竿时不推荐钓鱼赚钱。
- 普通矿洞层数不超过 120，骷髅洞穴独立显示层数。
- 社区中心全完成存档不生成交付建议。
- Joja 路线不生成社区中心交付建议。
- 存档切换后 tab 重置到重要提醒。

### 7.2 国际化验收

- 中文模式下重要提醒、推荐行动、详情弹窗不得出现可翻译英文。
- 英文模式下重要提醒、推荐行动、详情弹窗不得出现可翻译中文。
- 仓库内脱敏 fixture 覆盖至少 5 个代表性存档场景。
- 本机真实存档扫描只作为发布前人工辅助校验，不作为 CI 必需条件。

### 7.3 性能验收

- 大库存存档进入友谊维系无明显卡顿。
- 大量加工产物详情打开可滚动，不阻塞主界面。
- 切换已缓存存档不重新解析 XML。

### 7.4 工程验收

发布前必须通过：

```bash
npm run typecheck
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri:build -- --bundles dmg
```

GitHub Actions 必须能构建：

- macOS DMG。
- Windows NSIS 安装包。

## 九、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 存档字段差异 | 不同版本、平台、Mod 可能导致字段变化 | 保守解析，失败降级，增加脱敏 fixture |
| 推荐过度自信 | 部分状态无法从睡觉后存档确认 | 保持置信度和不确定项，不输出强结论 |
| 国际化反复遗漏 | 名称来源分散在存档、目录、规则、详情中 | 建立中英文泄漏测试和统一名称格式化入口 |
| 打包流程不稳定 | macOS DMG、Windows NSIS 环境差异 | GitHub Actions 固化构建，artifact 命名自动化 |
| 范围膨胀 | 1.1.0 容易变成规则百科全量工程 | 优先围绕推荐可信度，不做 UI 大改和新游戏 |
