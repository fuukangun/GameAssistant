# 游戏助手 1.2.0 - 产品需求文档

> **版本**: v1.1  
> **日期**: 2026-07-02  
> **基线版本**: 1.1.0  
> **目标版本**: 1.2.0  
> **主题**: 季节日历与后续规划能力  
> **核心原则**: 以日历 Tab 为主线，补全节日和生日规划能力；必要拆分大文件支撑新增功能，避免继续扩大单文件复杂度

---

## 一、背景

游戏助手 1.1.0 已围绕“推荐可信度增强”完成数据校准、推荐证据、不确定项展示、国际化和发布稳定性补强。当前应用已经可以基于存档生成当天提醒、推荐行动、角色技能、友谊维系、探索进度等内容。

1.2.0 需要解决的问题从“今天该做什么”扩展到“这一季接下来要提前准备什么”。现有能力存在以下不足：

- 生日提醒主要在当天触发，不能帮助玩家在生日所在周提前安排常规送礼次数。
- 当前节日数据严重不足，`festivals.json` 仅覆盖月光水母之舞，无法支撑完整季节总览。
- 玩家缺少当季 28 天视角，无法一眼看到生日、节日、季末节点和近期准备事项。
- 冬日星盛宴的神秘朋友送礼属于独立事件，不占周送礼上限，需要区别于普通 NPC 送礼提醒。
- `App.tsx`、`global.css`、`generatePlan.ts`、`parseSave.ts` 已接近或超过 1000 行，继续直接堆叠日历功能会增加维护成本和回归风险。

---

## 二、版本目标

### 2.1 产品目标

1. 新增日历 Tab，展示当前季节 28 天网格，标注 NPC 生日、节日和关键提醒。
2. 将生日提醒从“当天提醒”扩展为“生日所在周提前规划”，帮助玩家最大化本周送礼收益。
3. 补全星露谷主要节日数据，并提供 7 天、3 天、1 天和当天的节日准备建议。
4. 对冬日星盛宴建立独立提示规则，明确神秘朋友送礼不占周送礼上限。
5. 保持现有提醒和推荐行动逻辑稳定，日历 Tab 不与当天提醒重复输出冲突内容。
6. 在实现日历能力时同步进行必要组件和推荐逻辑拆分，降低大文件继续膨胀的风险。

### 2.2 目标用户

| 用户类型 | 1.2.0 重点收益 |
|---|---|
| 普通玩家 | 能提前知道本季生日和节日，不错过重要活动 |
| 友谊养成玩家 | 能在生日周提前安排常规送礼，生日当天再获得额外高收益送礼机会 |
| 效率玩家 | 能提前准备节日所需物品、金币、舞伴好感、展览会展品等 |
| 后期玩家 | 能以季节视角管理多 NPC 生日、节日和路线目标 |
| 后续开发者 | 日历功能落地时同步拆分关键大文件，后续迭代成本更低 |

## 四、功能需求

## 4.1 日历 Tab

目标：

- 在推荐区域新增 `calendar` Tab，作为“季节总览和提前规划”的入口。
- 日历默认展示当前存档日期所在季节和年份。
- P0 只支持查看当前存档日期所在季节，不提供手动切换上一季或下一季。
- 每季固定 28 天，按 4 周、每周 7 天展示。

日历规则：

- Day 1、8、15、22 为周日。
- 每周从周日开始，到周六结束。
- NPC 常规送礼周上限在周日重置。
- 当前日期高亮显示。
- 已过日期降低视觉权重，但仍保留事件信息。

日历格子必须展示：

- 日期。
- 当天是否为当前存档日期。
- NPC 生日事件。
- 节日事件。
- 冬日星盛宴等特殊事件标记。

验收标准：

- 任意季节都能显示 1-28 天完整网格。
- 当前日期高亮正确。
- 春夏秋冬的生日和节日能落在正确日期格子。
- 已过日期、今天、未来日期有清晰视觉区分。
- 移动端小宽度下仍保持 7 列布局，文本可截断或点击查看详情，但不得重叠。

## 4.2 生日提前预警

目标：

- 生日提醒不只在当天出现，而是从生日所在周的周日开始提示。
- 提醒核心从“避免浪费额度”调整为“最大化本周送礼总次数”。

送礼规则：

- 每个 NPC 每周最多接受 2 次常规礼物。
- 每天对同一 NPC 最多送 1 次礼物。
- 生日当天在本周已送满 2 次时，仍可突破上限追加第 3 次生日礼物。
- 如果生日当天本周未送满 2 次，生日礼物仍按游戏规则计入本周送礼次数。

可用天数判断：

- `daysBeforeBirthday = birthdayDay - currentDay`，只统计生日周内、当前日期到生日前一天的自然日。
- 生日前可补的常规礼物次数上限为 `min(daysBeforeBirthday, 2 - giftsThisWeek)`，因为同一 NPC 每天最多送 1 次礼物。
- 只有当 `daysBeforeBirthday >= 2` 且本周送礼 0 次时，才可提示“生日前送满 2 次常规礼物”。
- 只有当 `daysBeforeBirthday >= 1` 且本周送礼 1 次时，才可提示“生日前再送 1 次常规礼物”。
- 如果生日前剩余天数不足，只提示“还能补送 N 次常规礼物”或“已来不及补常规礼物”，不得承诺生日前可送满 2 次。
- `daysAfterBirthdayInWeek = weekEndDay - birthdayDay`，用于判断生日当天之后本周是否还有常规送礼机会。
- 如果 `giftedToday` 未解析，不能把今天当作确定可补送常规礼物的日期；文案必须提示“请先确认今天是否已送礼”，且不得承诺今天一定还能送。

预警窗口：

| 生日所在周 | 预警起始日 | 预警结束日 |
|---|---:|---:|
| 第 1 周 | Day 1 | 生日当天 |
| 第 2 周 | Day 8 | 生日当天 |
| 第 3 周 | Day 15 | 生日当天 |
| 第 4 周 | Day 22 | 生日当天 |

周日生日特殊说明：

- 如果 NPC 生日是 Day 1、8、15、22，生日当天就是该周第一天，不存在生日前的提前预警窗口。
- 周日生日当天送礼按常规额度计入本周 1/2，本周该 NPC 最多可送 2 次，包括生日当天这次。
- “生日周内，生日前”的预警规则不适用于周日生日。
- 周日生日仍需要当天 `must_do` 生日提醒，但不得提示“生日前先送满 2 次常规礼物”或“生日当天突破上限送第 3 次”。

预警文案规则：

| 场景 | 优先级 | 需求意图 | 参考文案 |
|---|---|---|---|
| 生日周内，生日前，今日是否已送礼未解析 | `info` | 保守提示玩家先确认今日送礼状态 | `{NPC} 的生日是 Day {X}，请先确认今天是否已经送礼；若今天还能送，可优先补 1 次常规礼物` |
| 生日周内，生日前，本周送礼 0 次，且生日前至少有 2 个确认可送礼日 | `info` | 引导玩家在生日前安排 2 次常规礼物 | `{NPC} 的生日是 Day {X}，生日前还有 {N} 个可送礼日，建议先送满 2 次常规礼物，生日当天可突破上限再送第 3 次` |
| 生日周内，生日前，本周送礼 0 次，但生日前只剩 1 个确认可送礼日 | `recommended` | 提醒玩家最多只能补 1 次常规礼物 | `{NPC} 的生日是 Day {X}，生日前只剩 1 个可送礼日，建议先送 1 次常规礼物，生日当天再送生日礼物` |
| 生日周内，生日前，本周送礼 0 次，但明天就是生日且今天已无法送礼 | `info` | 告知已来不及补常规礼物，只保留生日准备 | `{NPC} 明天生日，已来不及在生日前送满常规礼物；请优先准备生日礼物` |
| 生日周内，生日前，本周送礼 1 次，且生日前至少剩 1 天 | `recommended` | 提醒玩家生日前再补 1 次常规礼物 | `本周已给 {NPC} 送过 1 次，建议在 Day {X} 生日前再送 1 次常规礼物，生日当天可突破上限送第 3 次` |
| 生日周内，生日前，本周送礼 1 次，但生日前已无可送礼日 | `info` | 告知不能再补常规礼物，只保留生日准备 | `{NPC} 即将生日，生日前已无可补送常规礼物的时间；请优先准备生日礼物` |
| 生日周内，生日前，本周送礼 2 次 | `info` | 告知常规礼物已满，生日当天仍有额外机会 | `本周已给 {NPC} 送满 2 次常规礼物，Day {X} 生日当天仍可突破上限再送 1 次` |
| 当天生日，本周送礼 0 次，且生日后本周仍有剩余天数 | `must_do` | 保留生日送礼强提醒，并说明本周仍可安排后续常规礼物 | `今天是 {NPC} 生日，优先送出最爱或喜欢礼物；本周后续仍可继续安排常规送礼` |
| 当天生日，本周送礼 0 次，且当天是本周最后一天 | `must_do` | 保留生日送礼强提醒，但不承诺后续常规送礼机会 | `今天是 {NPC} 生日，优先送出最爱或喜欢礼物；今天是本周最后一天，本周已无后续常规送礼时间` |
| 当天生日，本周送礼 1 次 | `must_do` | 保留生日送礼强提醒 | `今天是 {NPC} 生日，优先送出最爱或喜欢礼物` |
| 当天生日，本周送礼 2 次 | `must_do` | 明确提示本周已满但生日可突破上限 | `今天是 {NPC} 生日，虽然本周已送满，但生日可突破上限再送 1 次` |
| 周日当天生日 | `must_do` | 只提示当天生日送礼，不提示提前送满或突破第 3 次 | `今天是 {NPC} 生日，优先送出最爱或喜欢礼物；今天是本周第一天，本周该 NPC 还可再收 1 次常规礼物` |

同周多生日：

- 当一周内存在多个 NPC 生日时，日历 Tab 必须显示汇总提醒。
- 汇总提醒需要列出 NPC 名称和生日日期。
- 汇总提醒不得把不同 NPC 的送礼次数混为同一个额度。

验收标准：

- 生日预警只在生日所在周周日到生日当天之间出现。
- 周日生日不生成生日前提前预警，只生成当天生日提醒。
- 生日前送礼规划必须考虑剩余可送礼天数；剩余天数不足时不得提示可送满 2 次常规礼物。
- `giftedToday` 未解析时，不得把今天作为确定可送礼日。
- 生日当天提示后续常规送礼机会时，必须确认生日后本周仍有剩余天数。
- 生日当天提醒能区分本周已送 0、1、2 次。
- 同周多生日时，每个 NPC 独立计算送礼状态。
- 中英文模式下均无硬编码混语。

## 4.3 节日数据补全

目标：

- 补全主要节日数据，使日历 Tab 能覆盖星露谷全年关键节日。
- 节日数据继续外置到静态 JSON，不把节日规则硬编码到 UI。

节日数据字段：

| 字段 | 说明 |
|---|---|
| `id` | 稳定节日 ID |
| `name` | 中文名 |
| `nameEn` | 英文名 |
| `season` | 季节 |
| `day` | 起始日期 |
| `endDay` | 可选，结束日期；仅用于夜市等连续多日节日 |
| `timeHint` | 当天参加时间和地点 |
| `timeHintEn` | 英文参加时间和地点 |
| `planningTips` | 提前准备建议 |
| `planningTipsEn` | 英文提前准备建议 |
| `relatedData` | 可选，金币、物品、好感度等智能建议数据 |

多日节日规则：

- 夜市使用 1 条节日数据表示，`day: 15`、`endDay: 17`。
- 日历网格中 Day 15、16、17 都显示夜市标记。
- 节日提前提醒在 Day 14 生成一次 1 天前最终提醒，覆盖 Day 15-17 整个夜市窗口。
- 夜市进行期间，每天可显示当天行动提醒，但不得每天重复输出同一条“明天开始夜市”的提前提醒。

本期至少覆盖：

| 节日 | 季节 | 日期 | 规划重点 |
|---|---|---:|---|
| 复活节 / Egg Festival | 春 | 13 | 彩蛋狩猎，预留金币购买草莓种子 |
| 花舞节 / Flower Dance | 春 | 24 | 需要 4 心舞伴，提前提升目标 NPC 好感 |
| 夏威夷宴会 / Luau | 夏 | 11 | 准备高品质食材参加汤品 |
| 月光水母之舞 / Dance of Moonlight Jellies | 夏 | 28 | 季末最后一天，确认夏季作物已收获 |
| 星露谷展览会 / Stardew Valley Fair | 秋 | 16 | 准备 9 格展品，覆盖多个类别和高品质物品 |
| 万灵节 / Spirit's Eve | 秋 | 27 | 迷宫和金南瓜 |
| 冰钓节 / Festival of Ice | 冬 | 8 | 准备鱼竿，参加冰钓比赛 |
| 夜市 / Night Market | 冬 | 15-17 | 连续 3 天，关注稀有商品和深海钓鱼 |
| 冬日星盛宴 / Feast of the Winter Star | 冬 | 25 | 准备神秘朋友礼物，不占周送礼上限 |

P0 验收以本表节日为准。后续若要覆盖更多节日或特殊事件，应作为数据补充任务单独进入范围。

验收标准：

- `festivals.json` 不再只包含单个节日。
- 每个节日至少包含中文名、英文名、季节、日期、中文/英文时间提示和中文/英文规划建议。
- 多日节日使用日期范围建模，并能在日历中连续展示。
- 静态数据加载和 fallback 逻辑保持兼容。

## 4.4 节日提前规划提醒

目标：

- 在节日前 7 天、3 天、1 天和当天生成不同粒度的提醒。
- 提醒必须服务玩家准备，而不是只告知节日存在。

提醒窗口：

| 距离节日 | 提醒类型 | 需求 |
|---:|---|---|
| 7 天 | 预告 | 告知下周或近期有节日，开始准备 |
| 3 天 | 准备提醒 | 展示关键准备事项 |
| 1 天 | 最终提醒 | 提醒明天参加时间、地点和关键物资 |
| 当天 | 行动提醒 | 展示参加时间和地点，避免与现有当天提醒重复 |

生成和去重规则：

- 节日提醒只在当前日期仍处于提醒窗口内时生成。
- 已过节日不再生成提前提醒或当天行动提醒。
- 同一个节日在同一天只显示 1 条最高优先级提醒，不同时输出 7 天、3 天、1 天等多条提醒。
- 如果节日当天已经由现有提醒系统输出同义提醒，日历 Tab 可以展示事件详情，但不应在提醒列表重复生成同义条目。

智能建议（P1）：

以下建议依赖当前金币、好感、库存或装备等存档数据。本期 P0 只要求输出通用 `planningTips`；以下智能建议作为 P1 增强体验，不阻塞 P0 日历发版。

| 节日 | 可结合的存档数据 | 示例需求 |
|---|---|---|
| 复活节 | 当前金币 | 提示可预留金币购买草莓种子 |
| 花舞节 | NPC 好感度 | 判断目标 NPC 是否满足 4 心舞伴条件 |
| 夏威夷宴会 | 背包/箱子食材品质 | 提示是否已有高品质食材 |
| 星露谷展览会 | 背包/箱子物品类别和品质 | 提示当前可覆盖展品类别数 |
| 冰钓节 | 鱼竿状态 | 无鱼竿时提示提前获取鱼竿 |
| 冬日星盛宴 | 礼物偏好和库存 | 提示准备最爱或喜欢礼物 |

验收标准：

- 同一节日不会在同一天重复生成多条含义相同的提醒。
- 当天节日提醒与现有提醒系统保持一致。
- 没有足够存档数据时，提醒可退化为通用规划建议，不输出强结论。

## 4.5 冬日星盛宴特殊规则

目标：

- 将冬日星盛宴的神秘朋友送礼视为独立事件，不参与普通 NPC 周送礼额度冲突判断。

需求：

- 日历格子中对冬日星盛宴显示特殊送礼标记。
- 提醒文案明确“神秘朋友送礼不占周上限，是额外送礼机会”。
- 如果无法从存档解析神秘朋友对象，不得猜测 NPC，只展示通用准备建议。
- 如果后续能解析神秘朋友对象，优先展示该 NPC 的最爱/喜欢礼物候选。

验收标准：

- 冬日星盛宴不会降低其他 NPC 的常规送礼建议优先级。
- 冬日星盛宴提醒不会被同周生日冲突提醒误判。

## 4.6 日历 UI 与交互

布局：

- 桌面端使用 7 列、4 行日历网格。
- 网格上方展示季节、年份和当前日期。
- 网格下方展示“本周预警”和“近期节日”列表。
- 移动端保持 7 列，但允许事件名称截断，并通过点击或详情区域查看完整信息。

视觉规则：

| 元素 | 需求 |
|---|---|
| 今天 | 使用主题高亮 |
| 生日 | 使用生日图标或等价视觉标识，并展示 NPC 名称 |
| 节日 | 使用节日图标或等价视觉标识，并展示节日名 |
| 已过日期 | 降低视觉权重 |
| 预警条目 | 根据 `must_do`、`recommended`、`info` 区分优先级 |

交互行为：

| 交互场景 | P0 行为 |
|---|---|
| 点击日期格子 | 展开或选中当天详情，显示当天全部生日、节日和提示；再次点击可收起或切换选中日期 |
| 点击生日事件 | 在当天详情中展示生日送礼说明、当前周送礼状态和可用礼物建议入口 |
| 点击节日事件 | 在当天详情中展示节日时间、地点和规划建议 |
| 点击预警条目 | 选中并高亮对应日期；如果关联多个日期，优先高亮最近的相关日期 |
| 键盘访问 | 日期格子和预警条目应可聚焦，回车或空格触发与点击一致的行为 |

验收标准：

- 日历 Tab 不需要说明性长文即可理解。
- 事件名称过长时不撑破格子。
- 中文和英文模式下布局均不重叠。
- 760px 以下宽度可用。
- 点击日期、事件和预警条目后，用户能看到对应事件详情或日期高亮。

## 五、技术与架构需求

## 5.1 数据模型

新增或扩展以下模型：

```ts
export type CalendarEventType = 'birthday' | 'festival' | 'special';

export interface CalendarEvent {
  id: string;
  day: number;
  endDay?: number;
  type: CalendarEventType;
  title: string;
  npc?: string;
  festivalId?: string;
  priority: 'must_do' | 'recommended' | 'info';
  /**
   * Static planning tips for the event, usually from festivals.json planningTips
   * or birthday display metadata. Dynamic save-dependent warnings belong in
   * CalendarWarning instead.
   */
  tips: string[];
}

export interface CalendarDay {
  day: number;
  weekNumber: number;
  dayOfWeek: 'sun' | 'mon' | 'tue' | 'wed' | 'thu' | 'fri' | 'sat';
  isToday: boolean;
  isPast: boolean;
  events: CalendarEvent[];
}

export interface CalendarWeek {
  weekNumber: number;
  startDay: number;
  endDay: number;
  days: CalendarDay[];
  warnings: CalendarWarning[];
}

export interface CalendarWarning {
  id: string;
  type: 'birthday_advance' | 'birthday_today' | 'multi_birthday_week' | 'festival_advance' | 'festival_today' | 'winter_star';
  message: string;
  priority: 'must_do' | 'recommended' | 'info';
  relatedDays: number[];
  eventIds: string[];
}
```

要求：

- `CalendarEvent.tips` 只承载静态规划建议，不依赖当前存档送礼次数、金币、好感度或库存。
- `CalendarWarning` 承载动态预警，由当前存档日期、送礼次数、NPC 好感、库存、金币等状态生成。
- 多日节日使用 `day` + `endDay` 表示日期范围，事件展开到日历格子时仍需覆盖范围内每一天。
- 类型定义优先放在 `src/shared/types.ts` 或日历模型文件附近，遵循现有类型组织方式。
- 日历模型必须能在不渲染 React 组件的情况下单元测试。
- `CalendarWarning` 必须包含稳定 `id` 和 `eventIds`，用于去重、点击跳转和测试断言。

## 七、验收标准汇总

1. 日历 Tab 可进入，显示当前季节、年份和 28 天网格。
2. 所有 NPC 生日能在正确日期展示。
3. 主要节日能在正确日期展示，夜市等多日节日可连续展示。
4. 生日预警从生日所在周周日开始显示。
5. 周日生日只生成当天提醒，不提示提前送满或突破第 3 次。
6. 生日前常规送礼建议必须受剩余可送礼天数约束，不输出无法完成的送满 2 次建议。
7. 生日当天能区分本周已送 0、1、2 次，并正确说明生日突破上限规则。
8. 生日当天若已是本周最后一天，不提示本周后续仍可常规送礼。
9. 同周多个 NPC 生日时，按 NPC 独立计算送礼状态。
10. 冬日星盛宴明确标注神秘朋友送礼不占周上限。
11. 节日前 7/3/1 天和当天能展示不同提醒，同一节日同一天只显示最高优先级提醒。
12. 夜市等多日节日能按日期范围连续展示。
13. 日历提醒与现有当天提醒不重复输出同义内容。
14. 点击日期、事件和预警条目能展示对应详情或高亮相关日期。
15. 中文和英文模式均可用，无明显混语。
16. 移动端 760px 以下无文本重叠或布局破裂。
17. 日历模型和提醒规则有自动化测试覆盖。
18. 日历主体代码不直接堆叠进 `App.tsx`。
